Overview

System Purge is a personal project exploring advanced vehicle physics and combat mechanics in Unreal Engine 5. The goal is to create an arcade-style driving experience that feels responsive and satisfying while maintaining a robust networked architecture for multiplayer support.

This project serves as a technical showcase for my C++ programming skills, physics system implementation, and understanding of UE5's replication framework.

Core mechanics revolve around a three-class dynamic: Speeder (Scout/Harvest), Smasher (Tank/CC), and Ranger (Mobile Base). Players must physically transport collected resources back to the Ranger to fund team-wide upgrades, creating a tense risk-reward loop.

Technical Implementation

Chaos Hover Physics

Custom 5-point suspension system with PD-Control orientation and Root Motion integration.

Analyzed from ChaosHoverMode.cpp, this module replaces standard movement with a robust physics simulation:

  • 5-Point Raycast: Detects ground at corners + center for stability.
  • Diagonal Cross-Product Normal: CalculateVehicleTiltNormal uses diagonals (FL-BR, FR-BL) to calculate a jitter-free ground normal.
  • Inertial Rotation: Custom PD Controller (Spring-Damper) aligns vehicle to terrain without snapping.
  • Root Motion Mix: FChaosMoverHoverRootMotionInput blends animation data with physics forces.

Network Replication

Server-authoritative movement with client-side prediction and lag compensation.

To ensure fairness in a competitive environment, the movement system is fully server-authoritative. Clients simulate locally for immediate feedback (prediction) and reconcile with server state corrections if desync occurs.

  • Client Prediction & Reconciliation (CMC-style)
  • Bandwidth optimization via quantized state updates
  • Lag compensation for hit registration

Gameplay Ability System

Deep integration of UE5 GAS for complex RPG mechanics and modular attributes.

Utilizes UAuraAbilitySystemComponent and multiple AttributeSets to manage granular stats like Torque, Hull Integrity, and Resource Cargo. All gameplay interactions—from damage to vehicle boosting—are driven by Gameplay Tags and Effects.

  • Unified Registry: UAuraItemDefinition is the polymorphic base class for all items, defining Identity (UI), Requirements (Mastery Level), and Abilities in a single asset.
  • Weapon Inheritance: UWeaponItemDefinition extends the base class to add "Hybrid Ballistics" config (Hitscan vs Projectile threshold) and "Overheat vs Reload" logic.
  • Tag-Based State: Replaces boolean flags with hierarchical Gameplay Tags (e.g., Item.Weapon.Rifle) for cleaner state management.

Horde AI Architecture

Optimized StateTree AI supporting hundreds of active agents.

Swarm enemies utilize a custom UHordeMovementComponent based on Boids flocking behavior, completely replacing the expensive standard CharacterMovement. Logic is driven by StateTrees for performance-friendly decision making.

  • Tick Throttling: Distance-based update frequency (up to 0.15s for distant enemies).
  • Fake Physics: "Impact Impulse" system simulates physical knockback without enabling expensive Ragdoll physics.
  • Pooling: Custom GTEnemyPoolSubsystem manages thousands of lifecycle events.

Hybrid Weapon System

Advanced ballistic simulation with Client-Side Prediction, Auto-Hitscan Switching, and Melee "Cleave Mass" logic.

Analyzed from PlayerRangeAbility.cpp and PlayerMeleeAbility.cpp, the weapon system handles complex networking and physics interactions:

  • Hybrid Ballistics: Automatically switches from Projectile to Hitscan for targets within 15m (100ms travel time) to ensure responsiveness.
  • Networked Recoil: Uses Unreliable RPCs for high-frequency fire events (>300 RPM) to prevent buffer overflows, with Server-Side Ammo validation.
  • Melee Physics: "Cleave Mass" budget system limits how many enemies a single swing can hit, calculated via UPlayMeleeAttackTask.
  • Predictive Knockback: Clients apply immediate visual impulse while waiting for Server Authority confirmation to minimize felt latency.
